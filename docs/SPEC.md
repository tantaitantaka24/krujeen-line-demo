# สเปก: เดโมระบบสั่งเบอร์เกอร์ + จองปลากระพง ผ่าน LINE OA (ร้านครูจีน)

อัปเดตล่าสุด: 30 ต.ค. 2569

## 1. เป้าหมาย
- รวมออเดอร์จากทุกช่องทาง (LINE, โทร, Messenger, โพสต์เฟส, หน้าร้าน) ไว้ในกระดานเดียว
- ให้ลูกค้าค่อย ๆ ย้ายมาสั่งผ่าน LINE โดยไม่บังคับ
- ค่าใช้จ่ายรายเดือนของร้านใกล้ 0 บาท (LINE OA ฟรี + Google Sheets + Apps Script + โฮสต์หน้าเว็บฟรี)
- เดโมอยู่ใน LINE OA ใหม่แยกจากบัญชีที่ใช้อยู่ ("เดโม ร้านเบอร์เกอร์ & ปลากระพง")

## 2. เมนู (แก้ได้ที่ `web/config.js` ที่เดียว)
| เมนู | ราคา |
|---|---|
| เบอร์เกอร์เนื้อ | 59 |
| เบอร์เกอร์ไก่ | 49 |
| เบอร์เกอร์กุ้ง | 49 |
| เบอร์เกอร์ปลา | 49 |
| เบอร์เกอร์ดับเบิ้ลไข่ | 39 |
| เคบับเนื้อเบอร์เกอร์ | 60 (ยืนยันแล้ว แก้ได้) |

ตัวเลือกเพิ่ม (ต่อชิ้น): ชีส +15 / ไข่ +10 / ขนมปังชาโคล +10

ปลากระพง (ต่อตัว): ไซซ์ 160฿ / ไซซ์ 180฿ — ชื่อไซซ์ยังเป็นค่าสมมุติ แก้ได้

## 3. การรับของ
- เบอร์เกอร์: รับหน้าร้าน หรือ ส่ง
- ปลากระพง: รับเอง หรือ ส่ง — จองเป็นรอบ (วันส่ง + จำนวนจำกัดต่อรอบ) เจ้าของเปิดรอบเองจากกระดาน
- ค่าส่ง: ยังไม่กำหนด (ตั้งเป็น 0 ไว้ก่อน แก้ได้ใน config)

## 4. การจ่ายเงินและการยืนยันออเดอร์ (ค่าเริ่มต้น)
ใช้กติกาเดียวกันทั้งเบอร์เกอร์และปลา

| กรณี | ผล |
|---|---|
| โอน + แนบสลิป | รับออเดอร์ทันที (สถานะ "รับแล้ว") |
| จ่ายหน้าร้าน / จ่ายปลายทาง | สถานะ "รอร้านยืนยัน" เจ้าของกด รับ / ไม่รับ |
| เจ้าของคีย์เอง (โทร/Messenger/เฟส/หน้าร้าน) | รับทันที |
| ลูกค้าที่ถูกติดป้าย "ต้องโอนก่อน" | เลือกจ่ายหน้าร้านไม่ได้ |

## 5. ฝั่งเจ้าของ (กระดานคิว `web/board.html`)
- เห็นออเดอร์วันนี้ทุกช่องทาง เรียงตามเวลา แยกสถานะ: รอยืนยัน → รับแล้ว → พร้อม → เสร็จ
- ปุ่ม "+ ออเดอร์ร้าน" สำหรับออเดอร์โทร / Messenger / เฟส / หน้าร้าน — ใช้ฟอร์มเดียว เลือกช่องทางด้วยปุ่มเดียว (ไม่ต้องแยกฟอร์มตามช่องทาง) เพื่อให้สถิติบอกว่าลูกค้ามาจากไหน
- ติ๊ก "รับเงินแล้ว" ได้ทุกออเดอร์
- ติดป้ายลูกค้า "ต้องโอนก่อน"
- เปิด/ปิดรับออเดอร์ชั่วคราว (ตอนยุ่งหรือของหมด)
- เปิดรอบปลา: วันส่ง, ปิดรับ, จำนวนตัว — เห็นแถบยอดจอง
- สรุปยอดวันนี้: ยอดรวม, รับเงินแล้ว/ยังไม่รับ, แยกช่องทาง, เมนูขายดี
- เสียงเตือนเมื่อมีออเดอร์ใหม่ (เมื่อเปิดกระดานค้างไว้)
- ป้องกันด้วย PIN พนักงาน (เฉพาะโหมดใช้งานจริง)

## 6. ฝั่งลูกค้า (หน้าสั่ง `web/order.html` เปิดใน LINE ผ่าน LIFF)
- แท็บ "สั่งเบอร์เกอร์" / "จองปลากระพง"
- เลือกเมนู + ตัวเลือกเพิ่ม, รับเอง/ส่ง, เวลา, ที่อยู่ + เบอร์ (บังคับเมื่อส่ง), วิธีจ่าย
- กดสั่งแล้ว: ระบบส่งข้อความสรุปออเดอร์ "จากลูกค้า" เข้าแชทร้าน → บอทตอบยืนยันด้วย reply (ฟรี ไม่กินโควตา)
- ปุ่ม "ออเดอร์ของฉัน" ดูสถานะได้เอง (ฟรี ไม่ต้องให้ร้านส่งข้อความแจ้ง)

## 8. ข้อจำกัดที่รู้แล้ว
- Apps Script อ่าน header `X-Line-Signature` ไม่ได้ จึงตรวจลายเซ็น webhook ไม่ได้ — บอทจึงทำแค่ตอบข้อความยืนยันจากเลขออเดอร์ที่มีอยู่จริง ไม่ทำอะไรที่มีผลต่อข้อมูล
- ปุ่ม Verify webhook ใน LINE Developers อาจขึ้น error เพราะ Apps Script ตอบกลับแบบ redirect แต่ข้อความจริงยังทำงาน (ทดสอบตอนติดตั้ง)
- ป้องกันการสั่งกวนได้ไม่ 100% — ลดความเสี่ยงด้วยขั้นตอนยืนยัน + กติกาข้อ 1–4
- โควตาข้อความฟรีของ LINE OA ต้องเช็คในบัญชีจริง (การตอบกลับไม่นับ, push/broadcast นับ)
